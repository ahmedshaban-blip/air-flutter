# MCP workspace/project configuration paths

**Research date:** 2026-11-04  
**Scope:** workspace/project-specific MCP configuration only, checked against `src/mcp/adapters/mcpServersAdapters.ts` and `src/mcp/adapters/specialAdapters.ts`. Sources are official product documentation or first-party repositories. “Unsupported” means the product does not natively consume the proposed file; a generated example may still be useful to humans, but must not be presented as an active configuration.

## Recommended production changes

1. **Fix definite paths:** Antigravity → `.agents/mcp_config.json`; Continue → a file inside `.continue/mcpServers/`.
2. **Stop offering unsupported workspace writes:** Cline and Windsurf/Cascade have documented user/extension-owned MCP configuration only; Claude Desktop is global-only.
3. **Remove or relabel non-native adapters:** Aider and AutoClaw do not consume the emitted MCP keys. `.mcp/multi-agent.templates.json` is a project-defined template, not a native CrewAI, AutoGen, or AutoGPT path.
4. **Modernize Copilot:** Prefer workspace-root `.mcp.json` with `mcpServers`; retain `.vscode/mcp.json` only as explicitly deprecated VS Code/local-harness compatibility.
5. **Correct user-scope portability:** Cline/Roo extension storage must not be modeled as `~/.vscode/globalStorage/...` on every OS; Devin/Cascade uses `%APPDATA%\devin\...` on Windows; Antigravity global is `~/.gemini/config/mcp_config.json`; AutoClaw general global settings are `~/.autoclaw/setting.json`.

## Bottom line

The current workspace paths are solid for **Cursor, Roo Code, Devin, OpenCode, and Codex**. VS Code’s path still works but is now the deprecated compatibility format. **Antigravity and Continue need concrete path changes.** **Cline, Windsurf, Claude Desktop, Aider, AutoClaw, and the combined multi-agent template must not be represented as native workspace MCP files where official support does not exist.**
